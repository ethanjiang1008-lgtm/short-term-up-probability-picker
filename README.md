# Short-Term Up Probability Picker

一个与 `seven-factor-stock-picker` 独立的 A 股短线研究项目。

## 目标

核心目标不是预测“明天涨停”或“连板”，而是回答：

> **今天尾盘看到这只股票，明天收盘上涨的概率有多高？**

当前阶段先用简单、可解释的规则产生 `score`。随着真实样本积累，再用历史结果把 score 转成经验上涨率。

主标签：`next_day_close > today_close`

辅助标签：`next_day_return >= +3%`、次日涨停。

## 两段式交易流程

### 第一段：尾盘

北京时间约 15:25 自动扫描，生成候选池并保存历史快照。

核心用途是发现：量价状态好、尾盘承接强、处于强势板块/市场环境中的个股。

### 第二段：晚间 + 次日

北京时间约 20:30 抓取公开财经新闻/上市公司资讯；北京时间约 08:45 再刷新次日观察池。

第二段把尾盘候选与晚间事件合并，重点寻找：

- 重大订单 / 中标 / 签约
- 业绩预告、业绩快报、财报超预期
- 政策、行业催化、涨价
- 新产品、产能、客户突破
- 并购重组、回购、增持等资本运作

次日仍要求人工确认竞价表现后再决定是否交易；没有可靠竞价数据前，系统不会伪造“竞价确认”。

系统允许“不交易”。评估同时关注胜率、平均盈利、平均亏损和期望收益。

## 新闻/公告雷达

第一版新增轻量级公开网页采集器 `scripts/news_crawler.py`，目前覆盖：

- 财联社电报移动页
- 证券时报
- e公司

这些来源公开提供滚动财经资讯/上市公司资讯，适合作为“事件发现层”。例如财联社的电报页面持续更新上市公司动态和市场信息，e公司也明确提供 7×24 小时上市公司标准化快讯。正式交易前仍应以公司公告/交易所披露为最终核验依据。 citeturn905575search0turn688610search0

爬虫目前采用“抓公开 HTML → 提取标题/链接 → 先按股票代码、再按股票简称匹配尾盘候选”的方式，保存到 `data/evening_news.json`。由于财经网站可能调整页面结构、限流或启用更强的反爬，代码将每个来源的失败状态单独记录，不因为单一来源失败而中断整个流程。

## 当前模型

只保留 5 个部分，避免系统过度复杂：

- 个股基础强度 25%
- 尾盘强度 25%
- 板块强度 20%
- 事件强度 20%
- 市场环境 10%

评分不是概率。只有历史样本达到最低数量后，才输出经验上涨率。

## 自动运行

现在只保留两段自动流程：

1. `tail-scan.yml`：工作日北京时间约 15:25，生成尾盘候选、补历史标签、更新回测报告。
2. `evening-next-day.yml`：工作日北京时间约 20:30 抓取新闻并生成次日观察池；北京时间约 08:45 只刷新次日观察状态，复用前一晚新闻，不重复抓取。

这样既保持“两段式”，又避免同一行情接口被多个 workflow 重复调用。

## 数据来源

行情数据第一版沿用现有 `seven-factor-stock-picker` 已验证的数据获取思路：新浪公开行情 API、A 股日 K 线、超时、重试和并发抓取。新闻层与评分层分离。

## 重要研究原则

1. 预测时点不可见的信息不能进入特征。
2. 回测按日期顺序进行，禁止随机打乱。
3. 概率只能来自历史结果校准，不能把人工 score 直接叫概率。
4. 盘后消息只能进入晚间流程，不能回填到尾盘信号。
5. 新闻抓取结果是“候选信息”，不是经过核验的公告事实。
6. 涨停、连板是收益分布中的高收益尾部，不是主目标。
7. 系统不做自动“自我学习”；迭代方式是“积累真实结果 → 回测 → 人工修改规则 → 再验证”。
8. 宁可少功能，也优先保证数据链路、标签和回测可靠。

## 当前状态

v0.4：两段式版本，包含新浪数据层、尾盘量价特征、简单市场环境、次日标签、每日历史快照、公开财经新闻/公告抓取、尾盘候选与晚间资讯匹配、次日观察池和基础回测闭环。

下一阶段重点不是继续堆因子，而是积累真实样本，验证“尾盘 score + 事件信息”是否真的能提高次日上涨率和期望收益。
