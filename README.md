# Short-Term Up Probability Picker

一个与 `seven-factor-stock-picker` 独立的 A 股短线研究项目。

## 目标

核心目标不是预测“明天涨停”或“连板”，而是回答：

> **今天尾盘看到这只股票，明天收盘上涨的概率有多高？**

当前阶段先用简单、可解释的规则产生 `score`。随着真实样本积累，再用历史结果把 score 转成经验上涨率。

主标签：`next_day_close > today_close`

辅助标签：`next_day_return >= +3%`、次日涨停。

## 交易流程

`尾盘候选 → 晚间消息/公告人工确认 → 次日竞价确认 → 决策`

系统允许“不交易”。评估同时关注胜率、平均盈利、平均亏损和期望收益。

## 当前模型

只保留 5 个部分，避免系统过度复杂：

- 个股基础强度 25%
- 尾盘强度 25%
- 板块强度 20%（暂留中性接口）
- 事件强度 20%（没有事件数据时取中性）
- 市场环境 10%

当前市场环境只使用涨跌幅榜估计，不引入额外复杂数据源。

评分不是概率。只有历史样本达到最低数量后，才输出经验上涨率。

## 自动运行

GitHub Actions 每个工作日北京时间约 15:25 运行一次：

1. 生成当日尾盘候选快照。
2. 给已经过去的候选快照补上下一交易日真实收盘结果。
3. 重新生成 60/65/68/70/75 分几个阈值的胜率与期望收益报告。
4. 把历史数据提交回仓库。

独立的 `daily-scan.yml` 只保留手动运行，避免重复定时抓取。

## 数据来源

第一版沿用现有 `seven-factor-stock-picker` 已验证的数据获取思路：新浪公开行情 API、A 股日 K 线、超时、重试和并发抓取。数据层与评分层分离。

## 重要研究原则

1. 预测时点不可见的信息不能进入特征。
2. 回测按日期顺序进行，禁止随机打乱。
3. 概率只能来自历史结果校准，不能把人工 score 直接叫概率。
4. 盘后消息只能进入晚间流程，不能回填到尾盘信号。
5. 涨停、连板是收益分布中的高收益尾部，不是主目标。
6. 系统不做自动“自我学习”；迭代方式是“积累真实结果 → 回测 → 人工修改规则 → 再验证”。
7. 宁可少功能，也优先保证数据链路、标签和回测可靠。

## 当前状态

v0.3：最小闭环版本，包含新浪数据层、量价/尾盘特征、简单市场环境、次日标签、每日历史快照、自动次日打标签、分数阈值报告和基础测试。

下一阶段不继续堆复杂模块，先观察真实历史样本是否证明高 score 对应更高的次日上涨率，以及期望收益是否为正。
