# Short-Term Up Probability Picker

一个与 `seven-factor-stock-picker` 独立的 A 股短线研究项目。

## 核心目标

不是预测“明天涨停”或“连板”，而是回答：

> **今天 14:30 左右触发运行时，这只股票明天收盘上涨的概率有多高？**

主标签：`next_day_close > today_close`。辅助标签：`next_day_return >= +3%`、次日涨停。

## 两段式流程

项目严格分成两个独立阶段，**第二阶段绝不覆盖第一阶段的结论**。

### 第一段：14:30 尾盘交易判断

北京时间约 **14:30** 触发运行。14:30 是运行时点，不要求把行情强制截断到 14:30；程序实际获取到行情时，以接口当时返回的数据为准。

输出 `data/daily_candidates.json`，代表第一阶段原始判断。

这份结果必须保持原样，不能被 15:30 后的新闻、公告或第二天信息改写。

如果某只股票在第一阶段已经达到较高确定性，则它就是**尾盘可执行候选**；较低确定性的股票则进入观察或不交易名单。

### 第二段：15:30 → 次日 09:30 隔夜复核

第二阶段在次日开盘前运行，统一分析完整窗口：

> **前一交易日 15:30 → 当日 09:30**

期间新出现的新闻、公告、政策、订单、业绩等事件，并和第一阶段候选逐一匹配。

输出独立的：

- `data/overnight_news.json`：隔夜信息采集结果。
- `data/preopen_review.json`：开盘前复核结果。

每只股票都会保留：

- `tail_score`：第一阶段原始分数，冻结。
- `preopen_score`：第二阶段独立复核分数。
- `score_change`：隔夜变化。
- `change_status`：`UPGRADE / DOWNGRADE / UNCHANGED`。
- `overnight_news_count`：影响该股票的隔夜新闻数量。
- `auction_action`：当前为 `WAIT_FOR_AUCTION`，后续接入可靠竞价数据再自动确认。

因此每天能直接看到：

**第一段为什么选它 → 15:30 后发生了什么 → 开盘前哪里变化了。**

## 股票扫描范围

数据源必须覆盖**几千只股票级别的全市场 universe**，不能只扫描涨幅榜前 150/500 只。

第一版扫描宇宙按以下规则过滤：

- 排除科创板（688）
- 排除创业板（300/301）
- 排除 ST / *ST / 退市整理等特殊股票
- 排除当前股价 > 100 元的股票
- 流通市值按配置限制在 20–300 亿元

因此“最终展示最多 20 只候选”和“前面只扫描 20/150/500 只股票”是完全不同的概念。系统应先覆盖完整合格股票池，再进行评分和排序。

## 新闻/公告雷达

第一期采用公开网页采集，当前接入财联社电报、证券时报、e公司。新闻层定位为“事件发现层”，不是直接交易信号；后续可继续接入中国证券报、上海证券报、上市公司公告/交易所披露等来源。

系统会尽量提取新闻中的发布时间；能确认时间的条目严格限制在上述隔夜窗口内，无法确认时间的条目会标记为 `unknown_time`，不会假装拥有精确时间。

新闻会先按 6 位股票代码匹配，再按股票简称匹配。后续将继续增加事件分类、去重、重大订单/中标/业绩/政策/涨价/并购等结构化识别。

## 当前模型

只保留 5 个部分，避免系统过度复杂：

- 个股基础强度 25%
- 尾盘强度 25%
- 板块强度 20%
- 事件强度 20%
- 市场环境 10%

评分不是概率。只有历史样本达到最低数量后，才用真实次日结果做经验校准。

## 自动运行

1. `tail-scan.yml`：工作日约 **14:30**，生成并冻结第一阶段尾盘候选，同时更新历史标签和研究报告。
2. `evening-next-day.yml`：负责 **15:30→09:30** 隔夜信息采集和第二阶段 pre-open review。
3. `pages.yml`：只负责把页面和已生成的数据发布到 GitHub Pages，不参与选股计算。

第二阶段不会修改 `data/daily_candidates.json`。

## 数据与研究原则

行情数据第一版沿用 `seven-factor-stock-picker` 已验证的新浪公开行情接口思路，并要求全市场分页覆盖、数据完整性检查、超时/重试和并发 K 线抓取。

1. 第一阶段使用程序实际获取到的当时行情数据，不把 14:30 强制当成数据截止点。
2. 第一阶段结果必须可追溯、不可被隔夜信息覆盖。
3. 15:30 后出现的新闻只能进入第二阶段。
4. 概率只能来自历史真实结果校准，不能把人工 score 直接叫概率。
5. 回测按日期顺序进行，禁止随机打乱。
6. 新闻是发现信号，公告/交易所披露是核验信息。
7. 涨停/连板只是高收益尾部，不是主目标。
8. 系统允许明确“不交易”。

## 当前状态

v0.5：全市场 universe 版本。第一阶段覆盖几千只级别的合格主板股票，排除科创板、创业板、ST 和股价超过 100 元的股票；第二阶段独立分析 15:30→09:30 隔夜信息。
