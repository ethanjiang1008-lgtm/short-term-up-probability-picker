# Short-Term Up Probability Picker

一个与 `seven-factor-stock-picker` 独立的 A 股短线研究项目。

## 核心目标

不是预测“明天涨停”或“连板”，而是回答：

> **今天 14:30 左右，这只股票明天收盘上涨的概率有多高？**

主标签：`next_day_close > today_close`。辅助标签：`next_day_return >= +3%`、次日涨停。

## 两段式流程

项目严格分成两个独立阶段，**第二阶段绝不覆盖第一阶段的结论**。

### 第一段：14:30 尾盘交易判断

北京时间约 **14:30** 运行，不等收盘。

输出 `data/daily_candidates.json`，代表：

> **仅根据截至约 14:30 已经可见的行情、量价、板块和市场环境得到的原始判断。**

这份结果必须保持原样，不能被 15:30 后的新闻、公告或第二天信息改写。

如果某只股票在第一阶段已经达到较高确定性，则它就是**尾盘可执行候选**，可以在尾盘直接交易；较低确定性的股票则进入观察名单。

### 第二段：15:30 → 次日 09:30 隔夜复核

第二阶段在次日开盘前运行，统一分析完整窗口：

> **前一交易日 15:30 → 当日 09:30**

期间新出现的新闻、公告、政策、订单、业绩等事件，并和第一阶段候选逐一匹配。

输出独立的：

- `data/overnight_news.json`：隔夜信息采集结果。
- `data/preopen_review.json`：开盘前复核结果。

每只股票都会保留：

- `tail_score`：第一阶段原始分数，冻结。
- `preopen_score`：第二阶段独立复核分数。
- `score_change`：隔夜变化。
- `change_status`：`UPGRADE / DOWNGRADE / UNCHANGED`。
- `overnight_news_count`：影响该股票的隔夜新闻数量。
- `auction_action`：当前为 `WAIT_FOR_AUCTION`，后续接入可靠竞价数据再自动确认。

因此每天能直接看到：

**14:30 当时为什么选它 → 15:30 后到次日 09:30 发生了什么 → 开盘前哪里变化了。**

## 新闻/公告雷达

第一期采用公开网页采集，当前接入财联社电报、证券时报、e公司。新闻层定位为“事件发现层”，不是直接交易信号；后续可继续接入中国证券报、上海证券报、上市公司公告/交易所披露等来源。

系统会尽量提取新闻中的发布时间；能确认时间的条目严格限制在上述隔夜窗口内，无法确认时间的条目会标记为 `unknown_time`，不会假装拥有精确时间。

新闻会先按 6 位股票代码匹配，再按股票简称匹配。后续将继续增加事件分类、去重、重大订单/中标/业绩/政策/涨价/并购等结构化识别。

## 当前模型

只保留 5 个部分，避免系统过度复杂：

- 个股基础强度 25%
- 尾盘强度 25%
- 板块强度 20%
- 事件强度 20%
- 市场环境 10%

评分不是概率。只有历史样本达到最低数量后，才用真实次日结果做经验校准。

## 自动运行

现在只保留两个工作流：

1. `tail-scan.yml`：工作日约 **14:30**，生成并冻结第一阶段尾盘候选，同时更新历史标签和研究报告。
2. `evening-next-day.yml`：工作日约 **09:10**，一次性完成 **15:30→09:30** 隔夜信息采集和第二阶段 pre-open review。

第二阶段不会修改 `data/daily_candidates.json`。

## 数据与研究原则

行情数据第一版沿用 `seven-factor-stock-picker` 的新浪公开行情 API / A 股日 K 线 / 超时 / 重试 / 并发抓取思路。

1. 任何时点不可见的信息不能进入该时点模型。
2. 14:30 尾盘结果必须可追溯、不可被隔夜信息覆盖。
3. 15:30 后出现的新闻只能进入第二阶段。
4. 概率只能来自历史真实结果校准，不能把人工 score 直接叫概率。
5. 回测按日期顺序进行，禁止随机打乱。
6. 新闻是发现信号，公告/交易所披露是核验信息。
7. 涨停/连板只是高收益尾部，不是主目标。
8. 系统允许明确“不交易”。

## 当前状态

v0.4：两段式研究闭环。第一阶段在 14:30 生成并冻结尾盘交易判断；第二阶段独立分析 15:30→09:30 隔夜信息，并以变化量形式生成开盘前复核结果。
